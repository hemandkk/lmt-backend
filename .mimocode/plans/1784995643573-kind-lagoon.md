# Fix: Employee Dashboard Date Filters Not Affecting Data

## Problem
`GET /api/v1/dashboard/employee?dateFrom=2026-07-20&dateTo=2026-07-25` returns the same data regardless of date range because several metrics ignore the `date_from`/`date_to` params.

## Root Cause Analysis

The `_metrics_for_scope()` function in `dashboard_service.py` calls multiple analytics methods. Some properly use date filters, others don't:

| Metric | Uses Date Filter? | Issue |
|---|---|---|
| `total_leads` | No | Always all-time count via `lead_counts["total"]` |
| `paymentStatus` | **No** | `payment_status_summary()` accepts NO date params |
| `paymentCollected` | Partial | Has `custom` field but response maps to hardcoded `total` |
| `leadsByStage` | Yes | `leads_by_stage()` filters on `Prospect.created_at` ✓ |
| `leadsByAdmissionStage` | Yes | `leads_by_admission_stage()` filters on `Prospect.created_at` ✓ |
| `examStats` | **No** | `exam_stats()` accepts NO date params |
| `target` | **No** | `sales_target_summary()` always uses `this_month` lead count |
| `incentive` | **No** | `incentive_status()` always uses `this_month` lead count |

## Fix Plan

### 1. `analytics_repository.py` — Add date params to methods that lack them

**`payment_status_summary()`** — Add `date_from`/`date_to` params, filter `Prospect.created_at`:
```python
def payment_status_summary(db, employee_id=None, date_from=None, date_to=None):
    # Add date filtering on Prospect.created_at using datetime_range_bounds
```

**`exam_stats()`** — Add `date_from`/`date_to` params, filter `Prospect.created_at`:
```python
def exam_stats(db, employee_id=None, date_from=None, date_to=None):
    # Add date filtering on Prospect.created_at
```

### 2. `dashboard_service.py` — Wire date params through `_metrics_for_scope()`

- Pass `date_from`/`date_to` to `payment_status_summary()` (currently missing)
- Pass `date_from`/`date_to` to `exam_stats()` (currently missing)
- **Replace `lead_counts["total"]`** with the `custom` count when custom date range is provided, or add a new `date_filtered` count
- **Replace `lead_counts["this_month"]`** for `target` and `incentive` with the date-filtered count when custom range is provided
- Pass `date_from`/`date_to` to `incentive_status()` when called from `_metrics_for_scope()`

### 3. `dashboard_service.py` — Fix `_metrics_for_scope()` target/incentive logic

Currently:
```python
month_leads = lead_counts["this_month"]  # Always current month
target = AnalyticsRepository.sales_target_summary(db, employee_id=employee_id, achieved=Decimal(str(month_leads)))
incentive = AnalyticsRepository.incentive_status(db, employee_id=employee_id, lead_count=month_leads)
```

Change to use date-filtered lead count:
```python
# When custom date range: use custom count. Otherwise use this_month.
filtered_leads = lead_counts.get("custom") if lead_counts.get("custom") is not None else lead_counts["this_month"]
target = AnalyticsRepository.sales_target_summary(db, employee_id=employee_id, achieved=Decimal(str(filtered_leads)))
incentive = AnalyticsRepository.incentive_status(db, employee_id=employee_id, lead_count=filtered_leads)
```
